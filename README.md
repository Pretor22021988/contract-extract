# contract-extract

Извлечение структурированных полей из договоров правилами — с проверкой на переносимость.

Правила писались, глядя на одну редакцию формулировок. Измеряются на двух: на своей и на второй, которую они не видели. Разрыв между этими двумя числами и есть содержание репозитория.

## Задача

Из текста договора извлечь двенадцать полей: стороны и их ИНН, предмет, цена, ставка НДС, размер предоплаты, неустойка, срок, применимое право, порядок разрешения споров.

Три обстоятельства делают задачу не сводящейся к набору регулярных выражений:

**Одно поле выражается по-разному.** Цена встречается как «1 000 000 (один миллион) рублей», «1 млн руб.», «1 000 000,00 руб., в том числе НДС 20%», «согласно приложению № 1».

**Поля отсутствуют.** В части договоров применимое право или подсудность не указаны вовсе. Метод обязан вернуть пустоту, а не подставить правдоподобное значение.

**Текст пришёл из распознавания.** Перепутанные похожие символы, разорванные переносами слова, лишние пробелы внутри чисел.

## Данные

Договоры синтетические: поставка, оказание услуг, подряд, аренда. Причина простая — на реальных договорах нет разметки, а без разметки нет метрики.

В генератор заложены две независимые редакции формулировок для каждого условия, отсутствующие поля, расхождение цены в тексте и в приложении, шум распознавания.

Базовый набор — 600 договоров, из них 135 с шумом, 19 с противоречием цены.
Усложнённый набор (`--hard`) — 600 договоров второй редакции, из них 199 с шумом, 23 с противоречием.

## Метод

Правила построены не на дословных шаблонах генератора, а на признаках: слово-подсказка плюс ближайшее значение нужного типа. Разница принципиальная. Правило, скопированное с шаблона генератора, даёт единицу на своей выборке и ноль на любой другой редакции того же условия — такая метрика не измеряет ничего.

Ни одно правило не угадывает. Подсказка не найдена — поле остаётся пустым. Ложное заполнение отсутствующего поля дороже пропуска: пропуск виден, выдуманное значение выглядит как результат.

Поверх извлечения работают проверки на самосогласованность: сумма прописью против суммы цифрами, срок против дат начала и окончания, ставка НДС против суммы налога. Их результат — отдельная метрика, а не служебная деталь.

Провал не размазан по всем полям, он сосредоточен в четырёх: применимое право, подсудность, цена, предмет. Реквизиты сторон, ИНН, проценты и сроки переносятся без потерь — у них жёсткая форма записи, и вторая редакция её не меняет.

Шум распознавания против незнакомой формулировки:

| набор | полнота на чистых | полнота на зашумлённых |
|---|---|---|
| базовый | 1.000 (5163 поля) | 0.987 (1490 полей) |
| усложнённый | 0.852 (4459 полей) | 0.838 (2197 полей) |

Шум стоит примерно полтора пункта на обоих наборах. Смена редакции формулировок — пятнадцать. Метод устойчив к битому распознаванию и хрупок к незнакомой формулировке условия.

Проверка на противоречие цены:

| набор | заложено | найдено | пропущено | ложных |
|---|---|---|---|---|
| базовый | 19 | 19 | 0 | 0 |
| усложнённый | 23 | 17 | 6 | 0 |

Ложных срабатываний нет ни на одном наборе. Пропуски на усложнённом наборе производны от полноты по полю `amount`: не извлечённую цену не с чем сравнивать.

## Что здесь неверно

`vat` — единственное поле с ложными заполнениями, около двух процентов. Правило принимает упоминание налога за указание ставки в договорах, где ставка не указана. По собственному критерию репозитория это самая дорогая из ошибок, и она не устранена.

## Методологическое ограничение

Усложнённый набор работает как отложенная выборка ровно до тех пор, пока правила под него не подгоняются. Дописать пару подсказок под `law` и `forum` и поднять полноту до 0.9 технически несложно, но после этого число перестаёт что-либо измерять. Для дальнейшей доработки правил нужна третья редакция формулировок, остающаяся закрытой на время разработки.

## Чего репозиторий не утверждает

Что метод пригоден для промышленного разбора договоров. Показано другое: как устроена метрика, которая ловит переобучение под шаблон, и насколько велик разрыв между выборкой разработки и незнакомой редакцией того же условия.

Синтетические данные не воспроизводят реальный договор. Они воспроизводят те свойства реального договора, которые ломают извлечение.

## Быстрый старт

```bash
pip install -r requirements.txt

python src/generate.py && python src/evaluate.py
python src/generate.py --hard --out data/hard.json && python src/evaluate.py --input data/hard.json

python -m pytest tests/ -q
```

## Структура

```
src/generate.py    генератор договоров с разметкой
src/extract.py     извлечение правилами и проверки на самосогласованность
src/evaluate.py    метрики по полям, сводные, по противоречиям и по шуму
tests/             13 тестов
```
