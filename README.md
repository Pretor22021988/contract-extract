# hybrid-search-ru

Гибридный поиск по русскоязычным юридическим текстам: BM25 плюс плотное представление, подбор веса смешивания по размеченной выборке.

Данные синтетические. Разметка релевантности известна из генератора, поэтому метрики считаются против эталона, а не оцениваются на глаз.

**Главный результат этого репозитория отрицательный, и он в разделе «Что не сработало».** Плотное представление, построенное на совместной встречаемости слов внутри корпуса, синонимы не связывает. Ниже показано, почему, и что из этого следует.

## Задача

Пользователь ищет судебную практику по правовой ситуации и формулирует запрос своими словами. Нужный документ описывает ту же ситуацию другими: в запросе «просрочка оплаты», в акте «задержка платежа»; в запросе «неустойка», в акте «пеня».

Лексический поиск такие документы не находит. Вопрос в том, чем закрыть разрыв и сколько это даёт.

## Как запустить

```bash
pip install -r requirements.txt

python src/generate.py            # корпус и эталон
python src/evaluate.py --sweep    # прогон по весу смешивания
```

Ничего не скачивается: плотное представление по умолчанию строится усечённым разложением матрицы «термин-документ» прямо на корпусе.

Ветка с трансформерной моделью включается ключом `--dense st` и требует `sentence-transformers`. В измерениях ниже она **не участвует** — модель не скачивалась.

## Устройство корпуса

Каждый документ описывает пару «категория спора плюс обстоятельство». У обоих элементов пары есть два способа выражения:

| | вариант A | вариант B |
|---|---|---|
| категория | неустойка, начисление | пеня, исчисление |
| обстоятельство | просрочка оплаты | задержка платежа |

Запросы формулируются в варианте A. Релевантные документы поделены между вариантами примерно поровну. Документы варианта B почти не разделяют с запросом слов — найти их можно только через синонимию.

Помехи заложены двух видов. Отвлекающие документы: та же категория, другое обстоятельство — лексически близки, но нерелевантны. Лексические ловушки: чужая категория с намеренно вставленными словами запроса.

Параметры прогона: 4000 документов, 120 запросов, 5,6 релевантных на запрос — 0,14% корпуса. Длина документа от 40 до 308 слов, медиана 94.

## Измерения

Вес `alpha` = 0 — чистый BM25, `alpha` = 1 — чистое плотное представление. Базовые линии стоят в той же таблице, что и гибрид.

| alpha | recall@10 | MRR | nDCG@10 | |
|---|---|---|---|---|
| 0.00 | 0.164 | 0.227 | 0.134 | чистый BM25 |
| 0.25 | 0.176 | 0.241 | 0.145 | |
| 0.50 | 0.204 | 0.262 | 0.164 | |
| 0.70 | 0.221 | 0.283 | 0.178 | |
| 0.85 | 0.233 | 0.303 | 0.190 | |
| 0.95 | 0.242 | 0.313 | 0.197 | |
| 1.00 | 0.237 | 0.319 | 0.198 | чистое плотное |

Максимум nDCG@10 приходится на `alpha` = 1,0. То есть **на этих данных смешивание с BM25 качества не добавляет**: лучший результат даёт плотная часть сама по себе.

Сложение обратных рангов, не требующее подбора веса: recall 0,202, MRR 0,292, nDCG 0,169 — хуже подобранного веса.

Доля запросов, где гибрид оказался хуже лучшей из одиночных систем: 15,8%. Средние значения это скрывают.

### Разбивка по способу выражения

Здесь видно главное.

| система | вариант A | вариант B |
|---|---|---|
| BM25 | 0.298 | 0.000 |
| гибрид | 0.431 | 0.000 |
| плотное представление | 0.431 | 0.000 |

Плотная часть заметно улучшает поиск документов, написанных **теми же** словами, что и запрос: 0,298 против 0,431. Она сглаживает морфологию и учитывает контекст.

Документы, написанные **другими** словами, не находит ни одна система. Ноль, а не малое значение.

## Что не сработало

Три вещи, и они содержательнее итоговых цифр.

**Разложение просило больше измерений, чем есть слов.** В первой версии стояло 300 измерений при словаре в 199 терминов. Разложение при этом ничего не сжимает, обобщения не происходит, и плотная часть вырождается в перевзвешенный лексический поиск. Обнаружилось при проверке размера словаря. Исправлено: измерений меньше словаря, значение по умолчанию 100.

**Мостовые документы не помогли.** Совместная встречаемость — единственный источник синонимии для такого подхода. Если «неустойка» и «пеня» нигде не стоят рядом, связать их не из чего. Добавил документы, употребляющие оба варианта, и прогнал по их доле: 0%, 15%, 35%, 60%, 85%. Recall по варианту B остался ровно нулевым при любой доле, а качество по варианту A при 85% начало падать — мостовые документы превратились в шум.

**Задача оказалась неразрешимой для этого класса методов, и это выяснилось только при разборе рангов.** Релевантные документы варианта B попадали на 450–900 место, варианта A — на 10–21. Причина: сотни нерелевантных документов той же категории содержат то же ключевое слово, что и запрос, а отличает релевантные только пара синонимов в обстоятельстве. Чтобы вытащить документ варианта B, нужно заранее знать, что «истечение срока» и «окончание периода» — одно и то же. Из четырёх тысяч коротких текстов это не выводится ни при какой настройке.

## Что из этого следует

Связывание синонимов требует знания, полученного **вне** этого корпуса. Разложение матрицы работает с распределением слов внутри коллекции и по определению не может знать того, чего в ней нет. Предобученная модель приносит это знание извне — она видела миллиарды слов, где «пеня» и «неустойка» стоят рядом.

Отсюда практический вывод, ради которого репозиторий и делался: **выбор между лексическим и плотным поиском решается не весом смешивания, а тем, откуда берётся семантика.** Подбирать `alpha` осмысленно только тогда, когда обе системы что-то находят. Здесь плотная часть на варианте B не находит ничего, и никакой вес этого не исправит.

Чтобы проверить это утверждение, запустите ветку с моделью:

```bash
pip install sentence-transformers
python src/evaluate.py --sweep --dense st
```

Ожидание: recall по варианту B станет заметно больше нуля, и оптимальный `alpha` сместится с единицы внутрь отрезка. Проверено не было — модель не скачивалась, и вписывать в таблицу неизмеренные числа я не стал.

## Ограничения

Морфология обрабатывается грубым усечением окончаний. Полноценная лемматизация дала бы лучше, но потянула бы словари и зависимости. Ограничение осознанное, влияет на обе системы одинаково.

Корпус синтетический и беднее реального: словарь 424 термина против десятков тысяч в живой коллекции. Абсолютные значения метрик к реальному поиску отношения не имеют. Переносимо здесь устройство измерения, а не числа.

Релевантность бинарная. В реальном поиске она градуированная, и nDCG считался бы иначе.

## Структура

```
src/generate.py    корпус, разметка релевантности, помехи
src/retrieval.py   BM25, плотное представление, смешивание, обратные ранги
src/evaluate.py    recall@k, MRR, nDCG@k, прогон по весу, разбивка по вариантам
```

## О данных

Реальных документов в репозитории нет. Все тексты порождены генератором из словаря общеупотребительных юридических терминов; совпадения с существующими судебными актами случайны и не подразумевались.
